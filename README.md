## 🔍 Overview

This project simulates a real-world QA engagement: testing the **Trello API** as if it were a product feature under test, from planning through execution and reporting — the same workflow a QA engineer would follow on a live team.

## ✅ What This Project Covers

- **Test Planning** — defining scope, objectives, and testing approach
- **Test Design** — applying black-box techniques (Equivalence Partitioning, Boundary Value Analysis) to design meaningful test cases
- **Test Case Documentation** — structured, traceable test cases with clear steps and expected results
- **API Testing with Postman** — validating endpoints, request/response structure, status codes, and data integrity
- **Test Scenarios** — mapping user-facing behaviors to testable conditions

## 🛠 Tools & Techniques Used

| Category | Details |
|---|---|
| API Testing Tool | Postman |
| Test Design Techniques | Equivalence Partitioning, Boundary Value Analysis |

- **Test Plan** — outlines what is being tested, why, and how

- **Test Cases** — granular, executable test steps with expected vs. actual results
